# Innovation Challenge Mapping

| Innovation Feature | Implementation Class(es) | How It Works |
| --- | --- | --- |
| **TF-IDF Duplicate & Related Detection** | `TfIdfSimilarityEngine`, `IncidentService.detectDuplicatesAndRelated` | Stopword removal + light stemmer + smoothed IDF cosine similarity. `>= 0.8` within 10m (same reporter + service) throws `DuplicateIncidentException`; `>= 0.2` within 24h links `relatedIncidentIds` and shows HTMX warnings. |
| **Auto-Categorization & Service Suggestion** | `KeywordClassifier`, `IncidentService.suggestCategory` / `suggestService`, `IncidentViewController.liveSuggestions` | Matches description keywords against DB `Category` and `ServiceEntity` catalogs in real time via HTMX while typing. |
| **AI Suggested Resolution + Gemini Adapter** | `AiTextService`, `LocalTfIdfAiService`, `GeminiAiService`, `AiConfig` | Surfaces resolution steps from highest-scoring similar resolved past incidents (`>= 0.2` cosine); optionally invokes Gemini `generateContent` via `RestClient` when `GEMINI_API_KEY` is set, falling back locally on any error. |
| **Smart Technician Recommendation Scoring** | `TechnicianRecommender`, `IncidentViewController.detail` | Ranks active technicians with explicit transparent score combining skill matches, per-service resolution experience, years, workload headroom, and availability. |
| **Service Dependency Graph & Root-Cause Correlation** | `ServiceEntity.dependsOn`, `OutageCorrelator`, `AdminController.catalog` | Flags `outageFlagged = true` when `>= 3` open incidents hit a service in 1h; propagates `"Possible root cause: <Upstream>"` to dependent services; renders live Mermaid dependency graph. |
| **Predictive SLA Risk Detection** | `SlaRiskPredictor`, `SlaInfo.evaluateStatus`, `SlaEscalationMonitor` | Tracks elapsed % separately for response & resolution; flags `AT_RISK` at `>= 80%` (and `projectedBreach` early for `P1`/`P2` at `>= 65%`) before deadline expires. |
| **Automated 3-Level Escalation** | `SlaEscalationMonitor.checkEscalation` | Unacknowledged incidents past response deadline escalate progressively: `0 (Tech) -> 1 (TeamLead) -> 2 (SYSTEM_ADMIN) -> 3 (IT_MANAGER)` with audit + owner alert. |
| **Event-Driven Observer & Multi-Channel Fallback** | `IncidentEventPublisher`, `AuditObserver`, `NotificationObserver`, `NotificationService` | Publishes 12 event types; routes `IN_APP` always and `EMAIL`/`SMS` for `P1`/`P2`/SLA; catches `NotificationDeliveryException` and falls back to `IN_APP` + audit. |
| **Real-Time HTMX Bell & Chart.js Analytics** | `NotificationController.bellFragment`, `ReportController`, `ReportService`, `reports/dashboard.html` | 15s HTMX polling for bell alerts and report KPIs, Chart.js priority/service/workload charts, avg feedback rating, and 7-day recurring problem detection. |
